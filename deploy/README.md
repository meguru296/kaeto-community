# 自建部署

1. 以普通账号安装 Node.js 22 或更新版本，克隆源码并运行 `npm ci --omit=dev`。按需用 `npm run check` 验证。
2. 创建独立运行账号，并准备只有该账号可以写入的 `DATA_DIR` 和 `UPLOAD_DIR`。程序目录应由部署账号持有，服务账号只有读取和遍历权限。部署后确认服务账号无法修改入口文件及静态资源目录。
3. 复制 `config.example.json` 为站点私有配置。对外运行时，填写自己的 `site.publicUrl`，启用 `security.secureCookies`，保持应用监听 `127.0.0.1`。通过可信本机代理部署时，才配置 `security.trustProxy` 为 `loopback`，并让代理覆盖来自客户端的转发头。可参考本目录的 Caddy 或 nginx 模板和 systemd 服务。
4. 应用启动前，使用与服务相同的配置和数据路径执行 `npm run admin -- <username>` 初始化管理员。自行部署 SMTP 和邮箱域名，通过 `MAIL_CONFIG_PATH` 指向独立私有配置。先测试验证码和找回密码，再按需启用注册并生成邀请码。
5. 正式环境可使用 PostgreSQL，连接串通过私有配置或 `DATABASE_URL` 提供。迁移或更新之前，先备份数据库、上传文件和配置，并在独立环境验证恢复。应用维护内存状态，始终只运行一个写入进程。
6. 依次更新实例的联系渠道、隐私说明、数据保留规则和启用的外部服务。数据及凭据文件保持在公共网页和版本控制目录之外。
